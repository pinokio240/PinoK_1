## 1. ПЛАН ИЗУЧЕДНОГО (факты разведки, main agent)

### 1.1 Краш «открыл видео и заблокировал экран» — ciber.txt
- `15:12:24.978 FATAL EXCEPTION: main`
- `java.lang.RuntimeException: Unable to create service re.pinok.service.VideoPlaybackService: java.lang.IllegalStateException: Session ID must be unique. ID=`
- Стек: `MediaSession.<init>(MediaSession.java:726)` ← `MediaSession$Builder.build(MediaSession.java:499)` ← **`VideoPlaybackService.onCreate(VideoPlaybackService.kt:101)`**
- Root-cause: и `VideoPlaybackService` (:95-101), и аудио `PlayerService` (:404) строят `MediaSession.Builder(...)` **без `.setId()`** → дефолтный ID = пустая строка. media3 требует уникальный session ID **на процесс**. Когда в процессе жива сессия аудио (PlayerService) и стартует видео-сервис (или наоборот/повторно) — вторая `build()` с тем же пустым ID роняет процесс.
- Сценарий юзера: видео открыто → экран заблокирован → `VideoPlaybackBus.onBackgrounded` стартует foreground-сервис → onCreate → build() → коллизия → крэш приложения.
- Доп. контекст лога: перед крашем процесс уже жил (PID 20480), после краша юзер перезапустил (PID 21086) — т.е. коллизия воспроизводится стабильно при повторном фоновом запуске.
