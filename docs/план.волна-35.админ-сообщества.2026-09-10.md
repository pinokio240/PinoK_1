## 2. Фаза 35-a — P0 «фундамент» (эта волна)

### A1. Модели: админ-поля `[x]` → коммит волны 35
- `VKApiClient.GroupInfo` += `isAdminSrv: Int` (`is_admin`), `adminLevel: Int`, `isAdvertiser: Int` (`is_advertiser`), `canMessage: Int` (`can_message`), `canSuggest: Int` (`can_suggest`), `memberStatus: Int` (`member_status`); хелперы `isManager = adminLevel >= 1 || isAdminSrv == 1` (сверка §5.1: порог показа «Управления» = `>=1`), `isAuthor = adminLevel >= 2`.
- `Models.kt` `Group` += те же поля (`is_admin`, `is_advertiser`, `can_message`, `can_suggest`, `member_status`); `isAdmin` (>=2) не менять — потребители Fix #144 завязаны на editor/admin.

### A2. `groupsGetById` — admin-блок в fields `[x]`
Default fields += `,is_admin,admin_level,is_advertiser,can_message,can_suggest,can_post,member_status`. Доп. поля игнорируются парсерами у остальных вызовов — безопасно.

### A3. `wallPost` — публикация от имени сообщества `[x]`
Параметры `fromGroup: Boolean = false`, `signed: Boolean = false` → `from_group=1`, `signed=1` (карта веб-флагов `official`/`signed`+`check_sign` из сверки §3.4; для VK API from_group/signed — верная карта).

### A4. CommunityScreen — блок «Управление» `[x]`
- Условие: `groupInfo.isManager` (admin_level >= 1 || is_admin==1).
- Карточка «Управление» между шапкой и лентой; пункты по сверке §4.1 (11 позиций веба) с реальной маршрутизацией:
  - «Настройки» → `AdminSettingsScreen` (35-b);
  - «Статистика» → `AdminStatsScreen` (35-b);
  - «Руководители» → `AdminPeopleScreen(tab=managers)` (35-b);
  - «Заявки» → `AdminPeopleScreen(tab=requests)`; «Чёрный список» → `AdminPeopleScreen(tab=banned)`;
  - остальные (Сообщения/Бизнес/Монетизация/Реклама/Страйки/Комментарии/Разделы/…) — честные disabled-строки «в следующей волне» (без выдуманных маршрутов).

## 3. Фаза 35-b — P1 «управление» (эта волна)

### B1. API: единый `groups.edit` + AdminSettingsScreen `[x]`

### B2. API: руководители + AdminPeopleScreen(вкладка «Руководители») `[x]`

## 5. Технические спецификации (для реализации)

### 5.1 Fields-блок админа для `groups.getById`
`is_admin,admin_level,is_advertiser,can_message,can_suggest,can_post,member_status`
- Веб-эталон (сверка §3.1): ответ `is_admin:1, admin_level:3, is_advertiser:1, can_post:1, can_message:1`.
- Web-enum (справочно, НЕ части VK API): `USER:0, MODERATOR:1, EDITOR:2, ADMINISTRATOR:3, HOST:4, EVENT_CREATOR:5, CREATOR:6, PSEUDO_ADVERTISER:100`. В VK API `admin_level` = 0..3 (1 модератор/2 редактор/3 администратор) — UI-градации только 1/2/3.

### 5.2 `groups.edit` — параметры (официальные)
`group_id` (обяз.), далее секциями: `title`, `description`, `screen_name`, `website`, `public_category`, `wall` (0/1/2/3), `photos`, `video`, `audio`, `docs`, `topics`, `stories`, `messages` (0/1/2), `enable_messages`, `enable_photo_comments`, `subject`, `action_button` (JSON), `main_section`, `secondary_section` и др. Ответ `{"response":1}`.

### 5.3 `groups.editManager`
`group_id`, `user_id`, `role` (moderator/editor/administrator), `contact_phone`, `contact_email`, `contact_position`; снятие = `remove=1` (без role). Ограничение: менять роли может только owner/administrator.

### 5.4 `stats.get`
`group_id` (может `-N`), `interval` (day/week/month), `interval_count`, `filters=visitors,views,reach,activity`, `timestamp_from/to`. Ответ `response[].{period, visitors:{views,visitors,…}, reach:{reach,reach_subscribers}, activity:{likes,replies,subscribes…}}`.
### 5.5 `stats.getPostReach`
`owner_id` (`-groupId`), `post_ids` (до 100 `postId`). Ответ: `reach, reach_subscribers, reach_users, likes, link_clicks, …`.

### 5.6 Баны/заявки
- `groups.getBanned`: `group_id`, `count/offset`, `fields` → `profiles[]` + `banned_info[]` (`end_date`, `reason`).
- `groups.banUser`: `group_id`, `owner_id`, `reason` (0-4), `end_date` (0 = навсегда), `comment`.
- `groups.unbanUser`: `group_id`, `owner_id`.
- `groups.getRequests`: `group_id`, `count/offset` → `profiles[]`.
- `groups.approveRequest`: `group_id`, `user_id`.

## 6. Критерии проверки волны 35

1. Сборка: `:app:compileDebugKotlin` без ошибок; nested-comments ALL CLEAN; brace depth=0 по изменённым файлам.
2. На сообществе с admin_level>=1 виден блок «Управление»; у обычного участника — нет.
3. Настройки: правка названия/описания/сайта сохраняется и отражается после перезагрузки экрана (`groups.edit` → getById).
4. Руководители: список ролей соответствует VK; смена роли/снятие применяются (тост + обновление списка).
5. Статистика: цифры за 30 дней сходятся с `vk.ru/groups/dashboard` порядком величин; охват постов > 0.
6. Заявки: approve переводит пользователя в участники; ЧС: unban убирает из списка.
7. Регресс: лента/Join/Leave/члены сообщества работают как раньше.
