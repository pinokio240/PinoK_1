## 2. API-МЕТОДЫ — fb.do (calls.okcdn.ru)

### 2.1. Общий формат запроса

```
POST https://calls.okcdn.ru/fb.do
Content-Type: application/x-www-form-urlencoded

method=<method_name>&format=JSON&application_key=CDLGIBMGDIHBABABA
&session_key=<session_key>&conversationId=<call_id>&<method_params>
```

### 2.2. Методы

| Метод | Параметры | Назначение | Когда |
|-------|-----------|-----------|-------|
| `system.getInfo` | — | Синхронизация времени (serverTime) | Первый запрос, перед startConversation |
| `vchat.startConversation` | conversationId, isVideo, protocolVersion=5, payload={is_video, with_join_link, join_by_link, community_user_id, caller_app_id}, onlyAdminCanShareMovie, externalIds | Инициация исходящего звонка → возвращает token + WS endpoint + TURN/STUN | Исходящий: при звонке |
| `vchat.hangupConversation` | conversationId, reason (HUNGUP/CANCELED/REJECTED/REMOVED/MISSED/BUSY/FAILED), peerId | Завершение звонка | Оба: при hangup |
| `vchat.clientStats` | data={items:[{name, value, string_value, ...}]} | Телеметрия (call_init/start/accepted/finish/codec_usage + 5с метрики) | Оба: на каждом этапе + каждые 5с |
| `auth.anonymLogin` | session_data={device_id, client_version=1.1, client_type=SDK_JS, auth_token=$Ksd, version=3} | Получение session_key + okcdn uid | При старте (ensureCallsSessionKey) |

## 4. WEBSOCKET — wss://videowebrtc.okcdn.ru/ws2

### 4.1. URL

```
wss://videowebrtc.okcdn.ru/ws2
  ?userId=<OKCDN_UID>              ← okcdn uid (из auth.anonymLogin)
  &entityType=USER
  &deviceIdx=0                       ← только входящий
  &conversationId=<UUID>            ← call_id
  &token=<base64-token>             ← из vchat.startConversation (исходящий) или conversation_params (входящий)
  &platform=WEB                     ← WEB (браузер) или android (PinoK)
  &appVersion=0.0.0
  &version=5                        ← версия протокола сигналинга
  &device=browser                   ← или HOTWAV Cyber 15 (PinoK)
  &capabilities=6D7F               ← hex битмаска возможностей
  &clientType=VK                    ← НЕ "USER"!
  &tgt=accept|start                 ← accept=входящий, start=исходящий
  &peerId=<okcdn_peerId>            ← опционально
```

### 4.2. Команды SEND (клиент → сервер)

| Команда | Sequence | Параметры | Когда |
|---------|----------|-----------|-------|
| `accept-call` | 1 | mediaSettings:{isAudioEnabled, isVideoEnabled, isScreenSharingEnabled, isFastScreenSharingEnabled, isAudioSharingEnabled, isAnimojiEnabled} | Входящий: принять звонок |
| `update-media-modifiers` | 1 (исходящий) / 3 (входящий) | mediaModifiers:{denoise:true, denoiseAnn:true} | Оба: после подключения |
| `change-options` | 2 | options:{FEEDBACK:true} | Исходящий: RTCP feedback |
| `change-media-settings` | 3-4 | mediaSettings:{...} | Оба: переключение mic/camera |
| `transmit-data` | 4-7 (исходящий) / 5-7 (входящий) | participantId, data:{sdp:{sdp}} или data:{candidate:{...}} | Оба: SDP/ICE обмен |
| `get-rooms` | 2 | withParticipants:false | Входящий: список комнат |
| `change-participant-state` | N | participantState:{state:{hand:"1"\|"0"}} | Оба: поднять/опустить руку |
| `custom-data` | N | data:{sdk:{type:"bad-net", rtt, loss}}, participantId:null | Оба: телеметрия качества сети |
| `hangup` | N | reason:"HUNGUP" | Оба: завершить звонок |
| `pong` | — | (текстовый кадр "pong") | Оба: ответ на ping |

### 4.3. Уведомления RECV (сервер → клиент)

| Notification | Параметры | Назначение |
|-------------|-----------|-----------|
| `connection` | stamp, peerId, endpoint, conversationParams:{turn, stun, serverTime, activityTimeout}, conversation:{id, state, topology, participants} | Первичное сообщение при подключении |
| `settings-update` | camera:{maxDimension, maxBitrateK, degradationPreference}, screenSharing:{...}, settings:{badNet:{rtt, loss}, goodNet:{rtt, loss}} | Настройки кодирования |
| `registered-peer` | peerId:{id, type:WEB_TRANSPORT}, platform, clientType, participantType, participantId | Новый участник подключился |
| `transmitted-data` | peerId, data:{sdp:{type, sdp}} или data:{candidate:{...}} | SDP offer/answer и ICE candidates |
| `accepted-call` | peerId, mediaSettings, capabilities, participantId | Исходящий: контрагент принял звонок |
| `media-settings-changed` | mediaSettings:{isAudioEnabled, isVideoEnabled} | Контрагент вкл/выкл mic/camera |
| `custom-data` | data:{sdk:{type, subtype, ...}} | Кастомные данные (например vk_decline_video_request) |
| `join-link-changed` | joinLink | Обновление ссылки-приглашения |
| `ping` | (текстовый кадр "ping") | Keepalive каждые ~3с |

### 4.4. conversationParams (в сообщении `connection`)

```json
{
  "turn": {"urls": ["turn:91.231.135.148:19302", "turn:90.156.236.95:19302"], "username": "<TURN_USER_MASKED>", "credential": "<TURN_CRED_MASKED>"},
  "stun": {"urls": ["stun:91.231.135.148:19302"]},
  "serverTime": 1791883866984,
  "activityTimeout": 120000
}
```

### 4.5. conversation_params (бинарный blob во входящем звонке)

Формат: `<original_len>:<base64-LZ4-compressed-JSON>`

Декодирование:
1. split(":") → [original_len, base64]
2. base64 → bytes
3. LZ4-декомпрессия → JSON
4. JSON поля: `tkn` (token), `wse` (ws endpoint), `wte` (webtransport), `trne` (TURN urls), `trnp` (TURN credential), `trnu` (TURN username), `stne` (STUN url), `srcp` (client type), `iv` (is_video), `ip` (WS IP addresses)

## 5. eventHub — wss://eh.vk.ru/

### 5.1. URL

```
wss://eh.vk.ru/?v=1.002&format=json&app_id=7879029&payload=<base64>
```

base64 payload = `{"api_version":"5.289","user_agent":"Mozilla/5.0..."}`

### 5.2. Протокол ehsp2

- WebSocket subprotocol: `["ehsp2", "<token>"]` (token из eventHub.getToken)
- Каждое сообщение: `0x01` + base64(JSON)

### 5.3. Сообщения

**SEND**: `{"id":3,"method":"execute","params":{"command":{"action":"subscribe_to_channels","payload":{"channels":{"<channelId>":<offset>,...}}}}}`

**RECV**: `{"result":{"success":true},"id":3}`

**RECV (event)**: `{"channel":{"label":"big_channel","queue":"-239203901"},"result":{"ts":1061,"old_version":1060,"new_version":1061,"updates":[[70022,-239203901,{"members_count":2566}]]},"id":null}`

### 6.4. ДВА механизма подписки (расшифровка JS-бандла a-5_*.js)

VK web использует **разные** API для подписки на разные типы очередей:

#### 6.4.1. calls-очередь — `calls.subscribeToQueue` (через calls.okcdn.ru)

```javascript
// JS-бандл m.vk.ru (a-5_371124dd5e57d323.js):
function eb(e,t,r){return createApi("calls.subscribeToQueue",!0)({
  anonym_auth_user_id:e, secret:t, device_id:r})}
function ek(e){let{base_url:r,queues:n}=e.queue_subscription_info,
  {key:i,timestamp:a}=n[0];return`${r}?act=a_check&key=${i}&id=${t}&ts=${a}&wait=20`}
```

**HTTP-запрос**:
```
POST https://calls.okcdn.ru/fb.do
Content-Type: application/x-www-form-urlencoded

method=calls.subscribeToQueue
&format=JSON
&application_key=CDLGIBMGDIHBABABA
&session_key=<session_key из auth.anonymLogin>
&anonym_auth_user_id=<okcdn uid из auth.anonymLogin>
&secret=<session_secret_key из auth.anonymLogin>
&device_id=<device_id>
```

**Response**:
```json
{
  "queue_subscription_info": {
    "base_url": "https://queuev4.vk.ru/im1180",
    "queues": [{ "key": "669dcf789f6f0a88...", "timestamp": 1227312319 }]
  }
}
```

**Что доставляет**: `incoming_call`, `call_accepted`, `current_calls_update`, `call_history_updated` — ВСЕ events с `entity_type:"calls"`.

**Авторизация**: `session_key` (из `auth.anonymLogin`) — НЕ web-токен, НЕ SAT-токен. БЕЗ cookies.

#### 6.4.2. multiaccount-очередь — `stickers.subscribeToQueue` (через web.api.vk.ru)

```javascript
// JS-бандл: createApi("stickers.subscribeToQueue")() — без параметров
```

**HTTP-запрос**:
```
GET https://web.api.vk.ru/method/stickers.subscribeToQueue?v=5.289&client_id=7879029
Authorization: Bearer <web_token>
```

**Response**:
```json
{
  "response": {
    "base_url": "https://queuev4.vk.ru/im1180",
    "key": "97faa2b0...",
    "ts": 976255910
  }
}
```

**Что доставляет**: messages/online/counters events — `entity_type:"im"` или LP-коды. **НЕ** `entity_type:"calls"`.

**Авторизация**: web-токен (vk1.a.*). Cookies не обязательны (SameSite=Strict, токен в Authorization header).

#### 6.4.3. Типичная ошибка (P0.42)

Использовать `stickers.subscribeToQueue` для calls-очереди. VK возвращает валидный `base_url/key/ts`, но ключ для **multiaccount-очереди** — events всегда `[]`. В логе:
```
poll: code=200 body.len=30 body={"ts":"...","events":[]}
```

**Правильно**: calls-очередь → `calls.subscribeToQueue` (calls.okcdn.ru с session_key); multiaccount → `stickers.subscribeToQueue` (web.api.vk.ru с web-токеном).

## 8. ЖИЗНЕННЫЙ ЦИКЛ — ИСХОДЯЩИЙ

```
1. Пользователь нажимает "Позвонить"
   → calls.callTo(peerId=<VK_UID_PEER>, source="im_header")

2. system.getInfo (fb.do) → serverTime

3. vchat.startConversation (fb.do)
   conversationId = UUID (клиент генерирует)
   isVideo = false
   externalIds = <VK_UID_PEER>
   caller_app_id = 7879029
   → response: {token, endpoint (wss://), turn_server, stun_server}

4. vchat.clientStats: call_init, source=outgoing

5. WebSocket connect → wss://videowebrtc.okcdn.ru/ws2?...&tgt=start

6. RECV: connection (conversationParams: TURN/STUN)
   RECV: settings-update (camera/screenSharing/badNet/goodNet)

7. SEND: update-media-modifiers (denoise:true, denoiseAnn:true)
```

### 16.1. HAR без JS-контекста = полкартинки

В P0.42 я смотрел HAR звонков и увидел: 29 вызовов `stickers.subscribeToQueue`, 0 вызовов `queue.subscribe`. Сделал вывод: «stickers — правильный путь». Это была **ошибка интерпретации**:
- 29 вызовов `stickers.subscribeToQueue` — это **multiaccount-подписка** (messages/online/counters), не calls.
- `calls.subscribeToQueue` идёт на `calls.okcdn.ru/fb.do`, а не на `web.api.vk.ru` — в HAR звонков этих запросов не было (ключ calls-очереди `669dcf...` уже лежал в localStorage браузера с прошлой сессии).
- JS-бандл `a-5_*.js` лежал рядом в `сигналинг_files/` — я не открыл его в P0.42. Если бы открыл, увидел бы `function eb(e,t,r){return createApi("calls.subscribeToQueue",!0)({anonym_auth_user_id:e, secret:t, device_id:r})}` — однозначный ответ.

**Правило**: когда вижу метод в HAR, обязательно проверить в JS-бандле, **какие параметры** он принимает и **для какой очереди** возвращает ключ. Валидный `base_url/key/ts` в ответе НЕ означает, что ключ правильный для нужной очереди.

### 16.2. Diagnostic-логи раньше парсера

В P0.43-r1 (c90554e) добавил diagnostic-логи в `pollLoop` — `poll: code=200 body=...`. Это сразу показало: events всегда `[]` — проблема в подписке, а не в парсере. Без этих логов мы бы продолжали гадать, парсер ли виноват или VK не присылает.

**Правило**: при отладке real-time канала (long-poll/WebSocket) первым делом добавить лог **сырого ответа** на каждый цикл. Не пропускать через парсер, пока не видно сырой body.

### 16.3. 3 раунда фиксов вместо 1

- P0.43-r1 (c90554e): добавил diagnostic-логи + переписал handler в SovaApp. Частично правильно, но не решало корень.
- P0.43-r3 (ac07af7): нашёл `calls.subscribeToQueue` в JS-бандле и починил подписку.

Если бы сразу открыл JS-бандл (а не только смотрел HTTP-запросы в HAR), P0.42 сделал бы правильно с первого раза.

**Правило**: HAR + JS-бандл — обязательная пара. HAR показывает что уходит/приходит, JS-бандл показывает **почему именно так** и **какие ещё методы есть**.

### 16.4. Метод может существовать, но не быть в HAR

`calls.subscribeToQueue` НЕ был в HAR звонков — потому что браузер уже имел сохранённый ключ в localStorage. Но метод **существует** и **активно используется** (видно в JS-бандле). HAR показывает только то, что произошло в записанную сессию, а не все доступные методы.

**Правило**: если в HAR нет ожидаемого запроса, это не значит, что его нет вообще. Проверить JS-бандл на наличие функции с таким именем.

### 16.5. Ключ в ответе ≠ правильный ключ

`stickers.subscribeToQueue` возвращает валидный `base_url/key/ts` — VK принимает эти ключи для `queuev4.vk.ru/im1180`, отвечает HTTP 200. Но это **multiaccount-ключи**, не calls-ключи. Разница видна только по `entity_type` в events (которых нет).

**Правило**: успешный ответ (200 + валидный JSON) НЕ означает, что подписка правильная. Проверить по `entity_type` в реально приходящих events, что подписка на ту очередь.

### 16.6. SAT-токен ≠ session_key

`queue.subscribe` (через web.api.vk.ru) требует **SAT-токен** (Service Access Token). У PinoK `sat=no` (см. лог `WebToken saved — user_id=..., sat=no`). Web-токен VK отклоняет с err=100.

`calls.subscribeToQueue` (через calls.okcdn.ru) требует **session_key** (из `auth.anonymLogin`). У PinoK session_key есть (`ensureCallsSessionKey: уже есть (len=156)`).

Это **разные токены** для **разных API**:
- web.api.vk.ru → web-токен (vk1.a.*) для messages/stickers API
- api.vk.com → SAT-токен для queue.subscribe
- calls.okcdn.ru → session_key (из auth.anonymLogin) для calls API

**Правило**: для calls-функционала использовать calls.okcdn.ru с session_key. НЕ пытаться работать через web.api.vk.ru (там нет calls-методов).
