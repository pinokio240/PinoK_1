**Три разных канала:**

1. **Старт/стоп расшифровки** (для всех, результат → «Расшифровки звонков»):

Валидация fileName: ≤128, regex-запрет `[#%&{}\/<>*?$!`"':@+|=]` (bridge@849931).
Событие: `asr-started {asrInfo:{initiatorId, movieId}, roomId}` — **ASR на сервере оформлен как movie-поток** (16131@446910); стоп: `asr-stopped {roomId}`. Копия в reconnect-снимке: `conversation.asrInfo`, `rooms.rooms[].asrInfo`.

3. **Текст транскрипции** — бинарный datachannel `"asr"`:

`calls.editParticipantName` / `calls.deleteParticipantName` / `calls.checkParticipantName` (bridge@969907+); UI: `calls_rename_participant`, поле ≤25 символов (maxLength:25, bridge@578524-зона).

### 6.7 Список участников (большие звонки)

`get-participant-list-chunk {listType:"GRID", fromIdx, count}` → `{chunk:{participants[], countBefore, countAfter, markerFound}}` (16131@309953, @425631); элементы participant содержат `mediaSettings, muteStates, unmuteOptions, participantState, markers, movieShareInfos, roles, sessionState` (16131@120410+). Полный список: `get-participants {externalIds}` / `get-participant-list-chunk` — HTTP-дубль `messages.getCallParticipants` c пагинацией по 1000 (bridge@962000-зона).

## §7. Зал ожидания (waiting hall)

- Флаг звонка: `ConversationOption.WAITING_HALL` (в `options`), capabilities-бит `waitingHall`.
- Участник в зале: `ParticipantStatus.WAITING_HALL` (локальный статус), экран `calls_status_waiting`.
- Список ждущих: WS `get-waiting-hall {fromId?, count?, backward?}` → `{totalCount, participants:[…]}`; UI догружает профили через `messages.getCallParticipants`-стиль (bridge@320074–323150).
- **Впустить**: WS `promote-participant {participantId}` (16131@309678; UI bridge@321717). Кнопки: `calls_waiting_hall_join/promote`, мультивпуск `calls_waiting_hall_list_multiple_promote`.
- **Вернуть в зал/выгнать**: `promote-participant {participantId, demote:true}`; у цели `promote-participant`-уведомление с `demote:true` → закрытие с `REMOVED` («Вас убрали», `calls_waiting_hall_removed`, 16131@408802).
- **Отклонить (refuse/forbid)**: `remove-participant {participantId, ban:false}` (§6.3).
- Нотификация админу о новых ждущих — баннер `calls_notification_users_in_waiting_hall_notification` (данные из `promote-participant`/session-state-событий; bridge@322850-зона).
- Анонимная LP-очередь: `calls.subscribeToQueue {anonym_auth_user_id, secret, device_id}` (bridge@202101).

## §9. Media-настройки (шумодав/качество/устройства/зеркало)

### 9.1 mediaSettings — единственный payload accept-call/change-media-settings

```
function Nr(e){ return Object.assign({isAudioEnabled:!1, isVideoEnabled:!1, isScreenSharingEnabled:!1,
  isFastScreenSharingEnabled:!1, isAudioSharingEnabled:!1, isAnimojiEnabled:!1}, e||{}) }   // 16131@93592
```
Wire `change-media-settings` = `{mediaSettings:{все 6 bool}}` (полный объект, не диф). **Битрейтов/`videoBitrateBps` в WS-протоколе НЕТ** — те были только в HTTP `vchat.joinConversation` okcdn-эпохи (PinoK это уже шлёт при join; держать).

### 9.2 Шумодав (auto/нейросетевой/простой/выкл)

UI-режимы `me.$2`: `NEURAL` («авто», default), `CLIENT` (нейросеть на клиенте при слабом железе), `SIMPLE`, `NONE` (bridge@544660). Маппинг на **серверные модификаторы** (9644@18175):
```
const n={1:{denoise:!0, denoiseAnn:!0}, 2:{denoise:!0, denoiseAnn:!1}, 3:{denoise:!1, denoiseAnn:!1}};
noiseCancellationModesByType = { NEURAL:n[config.noiseReductionMode||1], SIMPLE:n[2], NONE:n[3], CLIENT:n[3] }
```
Отправка: `update-media-modifiers {mediaModifiers:{denoise:bool, denoiseAnn:bool}}` (16131@308860). То есть:
- **NEURAL = {denoise:true, denoiseAnn:true}**, SIMPLE = {denoise:true, denoiseAnn:false}, NONE/CLIENT = {denoise:false, denoiseAnn:false}.
- `CLIENT`-режим дополнительно включает локальный AudioWorklet-эффект (`setAudioEffects`/`changeAudioEffect(["denoise"])`, bridge@498170–498922) — это клиентский DSP, не wire.
Сохранение выбора — localStorage `NOISE_CANCELLATION_MODE` (не сервер).

### 9.3 Качество видео (Оптимальное/Высокое/FHD)

UI-enum `Se {SD:"SD", HD:"HD", FHD:"FHD"}` (bridge@49913); размеры: **SD 640×360, HD 1280×720, FHD 1920×1080** (9644@10249: `e[e.SD=640]… HD=1280… FHD=1920`, высоты 360/720/1080). Применение — локальные capture-констрейнты + лимиты SDK:
```
on._params: videoMinWidth:428, videoMinHeight:240, videoMaxWidth:1280, videoMaxHeight:720,
            videoAspectRatio:16/9, videoFrameRate:25, screenFrameRate:15              // 16131@135484
async setLocalResolution({video:{width,height}, effect}){ … on.videoMaxWidth=…,
  this._mediaSource.setResolution(...), this._transport.onCameraResolutionChanged() } // 16131@~486400
```
Wire-эффекта у смены качества нет (кроме `change-simulcast`/`change-streams-priorities` в SFU-топологии). Зеркало (`IS_VIDEO_MIRRORED`) — чисто локальный CSS/рендер (9644-зона localStorage), wire нет.

### 9.4 Устройства

`changeDevice("audioinput"|"videoinput", deviceId)` — локальный трек-свитч; WS-палитра `switch-micro` — уведомление (16131 enum+notif); при DIRECT-топологии смена устройства может вызывать повторный SDP-оффер (transport-level). Capabilities: `videoTracksCount` (мультивидео до 30 слотов).

### 9.5 Прочее

- `hold {hold:bool, capabilities?}` — удержание (кнопка «держать», PinoK не требуется для Ж1–Ж9).
- `enable-video-suspend[(-suggest)] {enabled}` (DC #5/#6) — пауза приёма видео при плохой сети (сетевые приостановки видео = Ж10-зона, wire есть).
- `change-simulcast {mediaSource, simulcastInfo{streams:[{rid,width,height,fps,bitrate/1000}]}}` (DC #7) — ручное управление симулкастом.
- `change-streams-priorities {typedPriorities}` — приоритеты приёма (JSON-формат `p=N:sz=WxH:fit=…`, §10).

## §10. Layout / fullscreen / collapse / pin-тайлов

- `update-display-layout` (WS-JSON, когда DC недоступен): значения — строки (16131@320580, конвертер `Cn`):
  `"ss"` — стоп потока участника (не рендерить), `"kf"` — запросить keyframe, иначе `p=<priority>:sz=<W>x<H>:fit=cv|cn` (cv=cover/crop, cn=contain). Ключи — streamId вида `<participantId>:s<mediaType>:m<streamName>` (16131@~149700 `Rn/bn`).
  Wire: `{"command":"update-display-layout","sequence":N,"layouts":{"<streamId>":"p=1:sz=640x360:fit=cn"}}`.
- По DC — бинарник `#0` (16131@152862): `[0][0][seq][null][count][ {compactStreamId|streamId, stopStream|keyFrame|{priority?, w?, h?, fit?}} …][null]`.
- Отправитель в UI — LayoutService при grid/fullscreen-перекладке (bridge@172816: `this.sdk.updateDisplayLayout(i)`), троттл `requestDisplayLayoutThrottleMs:750`.
- **fullscreen/collapse — локальный UI-стейт** (`CHANGE_UI_MODE`, bridge@419895-зона), wire нет. Pin секций — тоже (§6.2 — только админ-серверный pin).

## §11. Watch together / URL-шаринг / vmoji / фон / трансляция

### 11.1 Watch together (совместный просмотр)
- Выбор фильма: `video.getWatchTogetherOwnerVideos`, `video.search {united_video_only:1, extended:1}` (API v5.167), `video.get {owner_id, videos, need_privacy}` (bridge@969107+).
- Старт: WS `add-movie {movieId:<int ov_id>, lang, gain:0.5, metadata:{title, thumbnails:[…]}}` → `{movieId, streamType}`; событие `movie-share-started {movieShareInfo{initiatorId, movieId, …}, roomId}` (bridge@306718, 16131@421344).
- Синхронизация: `update-movie {movieId, pause:true|false}` / `{movieId, offset:<sec>}` / `{movieId, gain, mute?}` (bridge@289954, 307185, 307352); live-стейт — `movie-update-notification {data:[{participantId,…}]}` (16131@410292).
- Стоп: `remove-movie {movieId}` → `movie-share-stopped`. «Выключить всем» — `enable-feature-for-roles {MOVIE_SHARE, [ADMIN,CREATOR]}` (bridge@300832). Режимы UI: `calls_stream_mode_movie/camera/screen`.

### 11.2 URL-шаринг (интерактивная доска/ссылка)
`start-url-sharing {sharedUrl}` / `stop-url-sharing` → `url-sharing-info-updated {initiatorId, sharedUrl?, roomId?}` (16131@~410900). UI-точка: `calls_interactive_board_is_shared_by_another`.

### 11.3 vmoji / виртуальный фон
- vmoji — **локальный рендер-пайплайн** (canvas/анимоji-стрим вместо камеры; MediaOption.ANIMOJI в mediaSettings; datachannel `animoji`, protocolVersion 1; worklet-файл `f92072ac-…` — аудио-визуализация). Wire-команд кроме mediaSettings/`participant-animoji-changed` нет.
- Виртуальный фон — upload картинки через `photos.getCallBackgroundsPhotoUploadServer` → `photos.saveBackgroundPhoto`, удаление `photos.delete`; применение — локальная сегментация (videoEffects). Отдельного WS-команда нет.

### 11.4 Трансляция (перевод/broadcast)
- Создание стрима: `video.startStreaming` → WS `record-start {movieId:<ov_id>, name, privacy:"DIRECT_LINK", groupId, roomId, streamMovie:true}` (§4); приватность/описание — `video.editStreaming {owner_id, video_id, name, desc, privacy_view}`; лайв-статус — `video.liveHeartbeat`; `calls.getBroadcast {call_id, hall_id?}` — данные трансляции звонка.
- UI: `calls_broadcast_*` (описание, приватность, время старта), `calls_translation_*` — стоп-модалки (`{owner_id, vid}` в стат-событии, bridge@629438).

## §12. Очередь событий (сводка по источникам)

Ин-кал события приходят **только по WS-уведомлениям** (§1.2) и datachannel'ам; LP (queuev4 `calls_<uid>`) в снапшоте фигурирует для: входящего (`calls_incoming_*`), анонимного зала (`calls.subscribeToQueue`), transfer-событий раздела «Звонки». Карты «LP-тип → payload» для ин-кал-фич нет — сервер ин-кал-стейт раздаёт через `connection`-снимок + диф-уведомления (это ключевое отличие от гипотезы «события через очередь»).

## §13. Честно: что НЕ найдено и гипотезы

1. **Значения-литералы hand/drat** (`D.RG`-сборщик): сам хелпер в чанке, которого нет в снапшоте. Формат `participantState{state:{…≤5-симв ключи}, stateUpdateTs}` доказан; значения `{"hand":"1"|"0"}` — вывод из SDK-enum `ParticipantStateDataValue{OFF:"0",ON:"1"}` (16131@480035), не из литерала. **Проверить при живом тесте.**
2. **`recover`, `switch-micro`, `record-set-conf`, `request-test-mode`** — есть в enum'е, JS-сендеров в снапшоте нет (клиентские пакеты других платформ/сервер). Payload'ы не восстановить из этого дампа.
3. **`get-waiting-hall` элемент списка** — точная схема участника в ответе (peerId/externalId/is_nft) видна только через UI-обёртки (`.peerId`, `.photo`, `.name`, `.is_nft`) — схема восстановлена по использованию, не по сериализатору.
4. **Точная схема `recordInfo`/`asrInfo`** внутри уведомлений — из кода видны поля `initiatorId`, `movieId` (asrInfo) и использование в UI (`calls_record_owner_title`); полный набор полей (state/время) не вырезан.
5. **Реакции: список `key`** — серверный (`calls.getReactions`); в дампе ключей нет (картинки грузятся с CDN).
6. **WebTransport-вариант конверта** (wt_endpoint) — в JS использует тот же JSON-конверт поверх QUIC-сессии; деталей frame'ов QUIC нет.
7. **`switch-room` для другого участника без update-rooms** — вызывается (16131@307553), но UI-ветка перемещения использует update-rooms; серверная семантика «админ перемещает любого» предполагается, не доказана.
8. **Ровно 62-значный vmoji-массив** в `f92072ac` — аудио-визуализация, к протоколу отношения не имеет (исключено).
9. **q_frame.html, log.txt, Новый текстовый документ.txt, 001073ce.wasm** — wire-сэмплов не содержат (localStorage/логгер/wasm-медиа).
