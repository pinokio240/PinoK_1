## §1. VK web: wire прикрепления и меню композера

### 1.1. Общая цепочка (канон VK)

```
(1) получить upload_url   — метод <ns>.get*UploadServer(...)
(2) POST multipart файл(ы) — на upload_url (поле photo|file|video_file, часто несколько photo1..N)
(3) сохранить              — метод <ns>.save*(поля из ответа шага 2) → {owner_id, id, access_key…}
(4) attachment-строка       — «type{owner_id}_{id}» (+ «_{access_key}», если VK выдал)
    стены/комменты: параметр attachments= (через запятую, до 10 вложений)
    сообщения:      параметр attachment= (VK принимает и список через запятую)
```

### 1.3. Меню веб-композера (пункты × источники)

**Пост-композер vk.com (стена/сообщество)** — по официальному посту VK (дек. 2024): основной контент «фото, видео и текст» (тайл с устройства, `<input type="file" multiple>`), затем дополнительное меню: **музыку, опрос, файл, место, кнопку** (+ карточка товара для сообществ). Ссылки на внешние ресурсы не отдельный пункт — URL в тексте превращается в сниппет; видео «по ссылке» живёт в диалоге выбора видео. Подарков в постах нет.

**Композер мессенджера vk.com web** (захвачен локально, `VK_WEB_COMPOSER_ANALYSIS.md`): скрепка `ConvoComposer__clip` → dropdown `DropdownReforged` с кнопкой **«Загрузить файл»** (`aria-label`, `<input type="file" multiple>` — фото/видео/доки одним системным пикером; на моб. web dropdown превращается в bottom-sheet `DropdownReforged__portal--bottomSheet`, max-width 362), плюс стикеры, голосовое (mic), эмодзи. Музыка/видео из библиотеки VK и подарки — выбор через поиск/панели композера, не через файловый инпут.

**Комментарии vk.com web** (`VK_IMPORT_API.MD` §9.3): `data-testid="show-attach-dropdown"` → `comment_upload_photo` (скрытый file input — только фото) + эмодзи; вложения показываются в `comment-input-attachments`.

**Мобильный web (m.vk.ru)**, по CSS-киту: композер собирается из тайлов `vkitMediaAttach` (каждый тайл — скрытый `inputActivable` file-input) и меню-листов `vkitDropdownActionSheetItem` (container/before/subtitle/…): т.е. пункты «Фото или видео» (с устройства), «Документ», «Из библиотеки VK» подаются как action-sheet со строчными пунктами.

## §3. СПЕКА: единое меню прикрепления (итог)

### 3.1. Принцип

Один компонент-вход = **существующий `UnifiedAttachMenu`** (расширенный), один лист библиотеки VK = **существующий `AttachmentPickerSheet`** (расширенный). VK web логика «сначала основной контент (фото/видео), потом дополнительное» отражается фиксированным порядком пунктов. Правило источников: у каждого типа до двух-трёх источников — **«С устройства»** (system photo picker / OpenDocument / камера) и **«Из VK»** (библиотека через AttachmentPickerSheet-паттерн, attach без upload), опционально **«По ссылке»** только там, где VK API даёт (`video.save link_url`). Пункт, чей VKA-метод отсутствует, **не показывается вовсе** (no-stub).

### 3.2. Итоговый список пунктов × источников

| № | Пункт | Источники | Wire (VKA существует / нужен) | Где показывается |
|---|-------|-----------|-------------------------------|------------------|
| 1 | **Фото** | (a) С устройства — photo picker, multi ≤10; (b) С камеры; (c) Из VK — альбомы пользователя (photosGetAll :15655 / photosGetAlbums) → attach `photo{owner}_{id}` без upload | все есть | Чат, комменты (оба), пост, (будущие фото/видео-комменты) |
| 2 | **Видео** | (a) Из VK — videoGet (:7617) → attach `video{owner}_{id}[_key]`; (b) С устройства — PickVisualMedia.VideoOnly → стену/комменты: video.save(wallpost=0)+videoUploadFile → attach `video{}` (videoSave :15366 + videoUploadFile :15411 есть, isClips=false уже умеет); ЛС: существующий uploadAndSendVideo (:9136, is_private=1); (c) По ссылке — `video.save(link_url)` (аддитивный параметр в videoSave) — только пост-композер | (a)(b) есть; (c) параметр нужен | Чат (a,b), комменты (a), пост (a,b,c) |

Поведение:
- Порядок пунктов фиксированный во всех поверхностях: **Фото → Видео → Музыка → Файл → Подарок → Опрос** (подарок/опрос скрываются контекстно флагами, как сейчас).
- Выбор источника: если у пункта один источник — открываем сразу (как сейчас Видео/Музыка → пикер); если несколько — нижний лист выбора источника («С устройства / С камеры / Из VK / По ссылке») в стиле AttachmentPickerSheet; недоступный источник не рисуем.
- `AttachmentPickerSheet` расширяется: + таб **«Фото»** (сетка альбомов/фото → attach `photo{}`), + таб **«Документы»** (docsGet → attach `doc{}`); таб «Видео» дополняется действием **«Добавить по ссылке»** (только когда пункт вызван из пост-композера и включён флаг).
- Лимит: до 10 вложений на пост/коммент (VK), фото-multi уже соблюдает; при превышении — честный тост, не молчаливое усечение.
- Upload-работа — в `SovaApp.appScope` (переживает навигацию, паттерн из VK_WEB_COMPOSER_ANALYSIS §7), видео — с `ProgressRequestBody`.
- Формат attachment-строк — единая точка сборки `type{owner}_{id}[_{access_key}]` (сейчас строка собирается в 4+ местах: PostDetail:1278-1296, Feed:3426-3444, Chat, VKA :6409/:8583 — при внедрении вынести в хелпер без смены поведения).
- Сигнатура `UnifiedAttachMenu` расширяется только дефолтными параметрами (обратно совместимо): новые `onPhotoFromVk`, `onFileFromVk`, `onVideoFromDevice`, `onLink`, `onPoll` + флаги `showPhotoFromVk` и т.п.

## §5. Честные отклонения и ограничения

1. **Аудио с устройства (upload в медиатеку) — отклонено.** `audio.getUploadServer`/`audio.save` — legacy; VK закрыл загрузку музыки для сторонних клиентов (монетизация/авторские права). Wire на актуальном моб. токене не подтверждён → в меню Музыка остаётся только «Из VK». Без заглушек.
2. **«Документ по ссылке» — отклонено.** `docs.add` принимает только `owner_id+doc_id(+access_key)` (копирование существующего дока, подтверждено vknet/офиц. описанием) — URL-параметра нет; в VK web «док по ссылке» тоже не существует. Пункт не вводится.
3. **Видео «по ссылке»** — только пост-композер; в ЛС/комментах VK web этого пункта не даёт. Спека повторяет веб.
4. **Заметки (`notes.add`)** — legacy-тип, из веб-композера убраны → отклонено.
5. **Место/карта, кнопка, товар (`market.add`), статьи** — отдельные подсистемы (гео-пикер, маркет-модуль), wire в PinoK отсутствует → вне унифицированного меню.
6. **Граффити** — upload-канал (`docs.getMessagesUploadServer type=graffiti`) существует и уже парсится в `docsSave`, но нужна рисовалка (новый UI) → отложено отдельной фичей, в меню не включено.
7. **Сторис-создание** — `stories.getPhotoUploadServer/getVideoUploadServer` в VKA отсутствуют, wire моб. токена не снят; просмотр уже есть, создание — отдельная волна (no-stub).
8. **Мульти-attachment в одном сообщении ЛС** — `messages.send` принимает список, но текущий `sendWithAttachment` шлёт один; видео уже уходит отдельным сообщением (:1658). Расширение — отдельный шаг, не часть меню.
9. **Живой DOM vk.com не снят**: пост-композер требует логина (антибот), dev.vk.com в момент исследования — maintenance (500). Меню web восстановлено по: официальному посту VK (wall-27902394_1128034), локальному захвату композера мессенджера, data-testid из VK_IMPORT_API.MD §9.3, CSS-киту m.vk.ru (`vkitMediaAttach`, `vkitDropdownActionSheetItem`). Формат attachment-строк и upload-цепочки подтверждены независимо (vk_api source, vknet, meta-описания dev.vk.com) — wire-часть спеки надёжна; композиция пунктов пост-композера — с оговоркой.
10. **Dead-пункт «Фото с камеры»** в PostDetail (:1061) и Feed (:3351) — преждесуществующий дефект (дефолты `showCamera=true`/`onCamera={}`), фикс входит в P0.
11. Сборка assembleDebug в песочнице невозможна (нет Android SDK) — проверка компиляции на стороне юзера после волны внедрения.
