## Решения (честно, в KDoc)
1. Один общий флаг `feedCarouselEnabled` управляет каруселью ВЕЗДЕ (лента/сообщества/профили/
   пост-детейл). Переименование в настройках: «Карусель фото в постах» + подзаголовок про все
   поверхности. Остаётся в секции «Лента» (главная поверхность, юзер уже знает место).
2. Общий компонент `ui/components/PostPhotoGrid.kt` (создаёт ОРКЕСТРАТОР до агентов, паттерн
   Task 4): публичный PostPhotoGrid = семантика FeedScreen PhotoGrid + FeedPhotoCarousel
   (VK web vkuiCarouselBase: свайп + полновысотные зоны-стрелки + счётчик + applicable-стрелка;
   carouselEnabled=false → прежний вид: 1-2 пейджер, 3+ сетка).
3. Общий компонент `ui/components/CommentAttachmentsView.kt` (создаёт ОРКЕСТРАТОР): компактный
   рендер аттачментов комментария: фото-сетка (1→200dp, 2→2×96dp, 3+→3×96dp), видео-превью,
   аудио-строка, doc-чип, голосовой-чип, ссылка-карточка, **стикер** (renderUrl если есть →
   иначе `https://vk.ru/sticker/1-{id}-256`, доказано дампом; размер ~128dp).
   Отклонения честно: poll/graffiti/gift/wall-репост в комментариях — пропуск с KDoc-следом.
4. Reply в ленте — 1:1 паттерн PostDetail Fix #209 (кнопка «Ответить», превью цели с ✕,
   «Ответ X» над текстом, reply_to_comment при отправке). Отправка в шите меняется на
   suspend-колбэк с Boolean-результатом → после успеха перезагрузка списка wallGetComments
   (сейчас список вообще не обновляется с сервера), при провале — оптимистичный убирается +
   тост с реальной причиной.
5. Клипы (ClipInteractionsSheet) — P1 следующей волны (вне слов юзера «к постам»).
