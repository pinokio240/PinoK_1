## 5. Находки

1. **AUTH no_password_flow задокументирован целиком**: `checkAuthCode` — это ПОЛЛИНГ
   (каждые 3.07 c, до ~60 раз, ~3 мин) пока пользователь не введёт код из push/SMS;
   fallback-цепочка push→SMS через `ecosystem.getVerificationMethods`/`sendOtpSms`;
   финал — `auth.validateAuthCode` → `login.vk.ru` SAT → `execute`. Прямо дополняет
   `AUTH-2FA-WHITEPAGE.md`: «белый экран» = ожидание ввода кода, поллинг уходит с ошибкой.
2. **`POST vk.ru/undefined` → 200, 105 KB text/html** — какой-то сервис собрал абсолютный URL
   с `undefined`; сервер вернул SPA-shell. Баг клиента (и маркер: SPA-shell отдаётся на любой путь).
3. **`api.vknext.net`** — новый домен: `GET vms.getAuthAppId` (370 B), `POST vms.getConfig`
   (видео-сообщения/кружки vms). Отдельный от api.vk.ru.
4. **Статика-зеркала**: тот же `/dist/...` отдаётся и с `st.vk.ru`, и с `st1-30.vk.ru` (шардирование).
5. **`batch.call` ×10** — SPA бандлит одиночные методы в батчи (экономия запросов).
6. `login.vk.ru` acts: `get_accounts`, `get_anonym_token`, `sign_in_sat` — cookie-домен переключения аккаунтов.
7. `queuev4.vk.ru/im1180` — long-poll очереди (IM/стикеры/事件), `eventHub.getToken`, `stickers.subscribeToQueue`.
8. `businessGroups.getShieldSettings` — верификация сообществ («щит»), screen=`verification`/`unlink_bid`;
   отвязка — legacy `verification.php?act=a_remove_verify`.

## 6. Порт в PinoK — что нужно и чего не хватает

**Уже есть:** живые web-куки в CookieManager (+ экспорт #SESSION-WEB-EXPORT), VkCookieJar на живом jar,
legacy-опыт (wkview, al_*).

**Нужно для админки:**
1. `hash` каждой формы — парсить из HTML страницы `…?act=edit` / фрагментов (`cur.hash`, `domData("…hash")`).
2. Заголовок/параметр `x-source` (аналитический, судя по всему опционален).
3. POST с куками на `vk.ru` (не api!) для legacy-частей; `web.api.vk.ru/method` — JSON POST.

**Чего не хватает в снапшоте (ограничение формата performance-trace):**
1. **Тела POST и тела ответов** — точные обязательные поля фрагментов/ответов `act=save`
   восстанавливались из JS, а не из трафика. Для полной верификации — HAR-экспорт вкладки Network
   (не performance-профиль!) на тех же страницах.
2. **Чанк админ-меню**: `owners.getMenu` вызван из чанка, не попавшего в трассу (нужен HAR или повторный заход).
3. Форматы ответов фрагментов `al_groups.php` (HTML в трассе не сохранён).

**План порта (минимальный):**
- Этап 1 (чтение): `owners.getMenu` + `groups.getContentForTabs` + фрагменты `al_groups.php` (GET/POST {act, group_id}) — рендер блоков.
- Этап 2 (сохранение): `groupsedit.php?act=save` — name/description/addr/website/age_limits + hash со страницы.
- Этап 3: вкладки (`groups.setTabsSettings`), модерация, shield.
