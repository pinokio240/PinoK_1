## ЧАСТЬ 1 — Контейнеризация (модульная архитектура разделов)

Идея: каждый раздел приложения (звонки, фото, аудио, …) — самостоятельный
Gradle-модуль-«контейнер», который экспортирует **capability** (навигацию,
настройки, рендеры вложений) в общий реестр. Хост строит UI из реестра.
Контейнер можно добавить/удалить **без потери функций остального приложения**:
нет контейнера → нет пункта меню/настройки/кнопки, ядро не падает
(например, чат при удалённом `photos` показывает заглушку «скачать файл»).

Правила зависимостей (зафиксированы в KDoc `:contracts`):
- `:feature:*` зависят **только** от `:contracts` + `:core:*`;
  друг от друга — НИКОГДА.
- Состояние контейнера изолировано (свои таблицы/префы/подкаталоги кэша).
- Хост строит UI из `ContainerRegistry.find<T>()`, graceful-деградация везде.
- Контракты (`:contracts`) — БЕЗ androidx/compose: минимальная поверхность
  (иконки мапит хост по `iconKey`, не модуль).

### Правило владения UI (решение пользователя 2026-09-01 — ЗАФИКСИРОВАНО)

- **Ядро (`:app`) владеет НАВСЕГДА** (не зависит от контейнеров):
  - оболочка боковой панели (drawer) и Dock (лента/сообщения/музыка/видео/профиль);
  - экран **Настроек** как таковой — общие ядерные вкладки (интерфейс, сеть,
    уведомления, приватность, безопасность…);
  - пункт **Выход**.
- **Контейнер экспортирует два UI-capability**, которые появляются ТОЛЬКО пока
  контейнер зарегистрирован в `ContainerRegistry`:
  - `NavEntry` → кнопка в боковой панели с названием контейнера;
  - `SettingsSection` → своя вкладка в Настройках (динамически добавляется
    в `PrimaryScrollableTabRow` после ядерных, сортировка по `order`).
- Подключили контейнер → кнопка на панели + вкладка в настройках появились
  сами; убрали контейнер из реестра → оба исчезли, ядро (чат, настройки, выход)
  живо без изменений.
- Где сейчас живёт то, что переведём на реестр (Этап 1.4):
  - пункты панели — `Screen` (`ui/navigation/Screen.kt`) + drawer в `SovaNavHost.kt`
    (захардкожено);
  - вкладки настроек — `SettingsTab` enum в `SettingsScreen.kt`
    (`PrimaryScrollableTabRow` + `HorizontalPager`).
- Реестр пуст (сейчас) → панель и настройки показывают только ядерные пункты.

## Правила процесса (не нарушать)

1. **Коммиты**: `fix(calls): #CALLS-XXX-NN — описание с ссылками на лог (время/строки)`;
   контейнеризация — `arch(containers): #ARCH-CONTAINERS Этап 1.N — …`.
   Всё пушим в `origin/PinoK`.
2. **BuildStamp**: bump в КАЖДОМ коммите звонковой логики. Текущее значение
   `calls-2026.09.02-3`. (Нарушение 85e83909..d09888de исправлено `f2f6b17d`.)
3. **Доки после каждого этапа**: worklog.md (шаблон Task ID/Agent/Task/Work Log/
   Stage Summary) + профильные файлы (`звонки.md`, `HISTORY.md`, этот план).
4. **Приложение работоспособно после каждого этапа** — этап маленький,
   собрался → коммит → push.
5. Сборка/тест на устройстве — за пользователем (в песочнице нет Android SDK).
