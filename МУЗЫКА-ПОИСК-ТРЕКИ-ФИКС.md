# Fix #282 — Музыка: в поиске отсутствуют треки («ищутся только альбомы»)

> Отчёт по задаче «а почему в музыке только альбомы ищутся, а треки
> отсутствуют?» (2026-09-07). Ветка: `PinoK` · зона: `VKApiClient`
> (audioSearchWithSections / audioSearchCatalogFallback). UI-код
> (MusicScreen) НЕ менялся — секция «Треки» там уже была и всегда была
> пустой из-за API-слоя. Регрессий Fix #281/#283 нет: AsyncAppLog,
> дедуп-ключи, collectLatest, rethrow CancellationException — не тронуты.

---

## 1. Симптом (от пользователя)

Поиск в разделе «Музыка» (вкладка «Моя музыка», inline-поле) возвращает
секции «Артисты» и «Плейлисты» (альбомы), но секция **«Треки» всегда
пустая**.

## 2. Диагноз — треки парсились не из того поля ответа

Задокументированная структура ответа `catalog.getAudioSearch`
(need_blocks=1) — HISTORY.md, 2026-08-17, подтверждена живым устройством
(`audioGetAudiosByArtist` получает 38 треков «Баста» именно оттуда):

```
response = {
  audios:     [ ...ТРЕКИ ПОИСКА (главное место)... ],
  albums:     [ ...альбомы... ],
  playlists:  [ ...плейлисты (type=album)... ],
  links:      [ ...артисты (meta.content_type=artist)... ],
  profiles:   [ ...пользователи... ],
  catalog:    { default_section, sections[].blocks[] }   // suggestions/заголовки
}
```

**Корневая причина:** `audioSearchWithSections` доставал треки ТОЛЬКО из
`blocks[]` (через `parseCatalogSectionExtended`), а `response.audios[]`
никогда не читался. Блоки в поисковом ответе лежат в
`response.catalog.sections[].blocks[]` (top-level `blocks[]` у поиска
пуст/отсутствует) и треков поиска не отдают. Итог по каждому запросу:

```
tracks = []  ← всегда
artists = links[]            ← работало
playlists = albums[]+playlists[] ← работало («альбомы ищутся»)
```

Далее срабатывал ранний `return` Fix #281 — «если catalog дал хоть
что-то — вернуть»: возврат происходил с НУЛЁВЫМИ треками, и до
классического `audio.search` (который даёт треки для direct-токенов)
код не доходил никогда. Двойная защита от треков, оба барьера — на
пути треков.

Дополнительно тот же слепой патч был в `audioSearchCatalogFallback`
(Fix #266): fallback-поиск тоже читал только blocks.

## 3. Что изменено (VKApiClient.kt, 3 функции + 1 новая)

### 3.1. НОВОЕ: `parseTracksFromCatalogSearchResponse(resp, limit, seen)`

Парсер треков из `response.audios[]` — первичный источник треков поиска.
Дедуп по (ownerId, id) через общий `seen`-набор (пересечения audios[] и
блоков возможны). Треки без URL НЕ фильтрует — решение на стороне
вызывателя (withSections показывает «доступно по подписке», fallback
пропускает непроигрываемые).

### 3.2. `audioSearchWithSections` — 3 правки

| Было | Стало |
|---|---|
| Треки только из `section.blocks` | + `response.audios[]` через новый парсер (первичный источник), blocks — легаси-добор; общий дедуп |
| Ранний return при «tracks \|\| artists \|\| playlists non-empty» | Ранний return **только при ненулевых треках**; если треков нет — провал в `audio.search` (даёт треки для direct-токенов), затем finalize как раньше |

Бюджет HTTP-вызовов не ухудшен: audios[] парсится из УЖЕ скачанного
catalog-ответа (0 доп. запросов); extra `audio.search` возникает только
в edge-case «catalog дал артистов/плейлисты, но ноль треков» — и именно
он лечит empty-треки для direct-токенов.

### 3.3. `audioSearchCatalogFallback` — тот же фикс

Сначала `response.audios[]` (с фильтром url-blank), затем легаси-добор
из blocks. raw-JSON теперь берётся напрямую через `catalogGetAudioSearchRaw`
(раньше через `catalogGetAudioSearchExtended`, терявший top-level поля).

## 4. Матрица проверки (пользователю)

Сборка: `assembleDebug`. Теги в логе: `MusicScreen`, `VKApiClient`.

1. **Треки в поиске**: Музыка → «Моя музыка» → запрос («кристалл»,
   «баста») → секция «Треки» заполнена вертикальным списком; в логе
   `audioSearchWithSections(catalog): query='...' → N tracks, M artists,
   K playlists` с N>0.
2. **Играются**: тап по треку из поиска → воспроизведение (у треков из
   catalog url может отсутствовать для неподписчиков — такие показываются
   в списке, но тап уходит в `audioGetById`-дозагрузку URL, прежнее
   поведение).
3. **Секции в сборе**: Артисты + Плейлисты не пропали, дубликатов нет
   (дедуп Fix #281 жив).
4. **Быстрый набор**: приложение живо, без ANR (AsyncAppLog Fix #281 не
   регрессировал), результаты не мигают (collectLatest жив).
5. **Direct-auth токен** (если есть аккаунт): при пустом catalog треки
   приходят из `audio.search` — в логе fallback-ветка.
6. **Регресс-дым**: «перемешать все», скачивание, ArtistDetail (треки
   артиста — тот же `response.audios[]`-путь, теперь общий парсер).
