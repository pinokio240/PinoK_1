## 18-α. Мессенджер: «печатает» (полный приёмный контур) + каналы: счётчики и сеть

**Текущее состояние (факты):**
- Typing-события парсятся: `realtime/LongPollClient.kt` (эмит `LongPollEvent.Typing` для ЛС/чатов), `realtime/ChannelWebSocketClient.kt` (свой typing-тип).
- Потребление: `ChatDetailScreen.kt:2212-2223` (collect Typing для пира) + стейт `msgTypingIndicator` (609). В `MessagesScreen.kt` Typing НЕ потребляется (rg Typing = 0 вхождений) — список диалогов «печатает» не показывает.
- Каналы: `MessagesScreen.kt` — табы 0=Все/1=Каналы/2=Непрочитанные; `isChannel = group && can_write.allowed=false` (#DIALOGS-TAB); лимит 40 (Fix #127), #MODERN-SYNC-CURSOR для полноты каналов.
- Сводный счётчик непрочитанных (бейдж «Сообщения» в доке) — источник трассировать (SovaApp/MainActivity/SovaNavHost): вероятно агрегация unread_count диалогов БЕЗ исключения каналов.

**VK web/API паттерны (явно):**
- LongPoll типы: `61` — пользователь печатает в ЛС (`user_id`), `62` — в беседе (`user_id`, `chat_id`). Индикатор живёт ~5 сек без продления, затем гаснет (VK web: таймаут + замена при новом событии).
- Исходящий «печатает»: `messages.setActivity(type=typing, peer_id=...)` — интеграционный шаг 18-θ (после волны, оркестратором, чтобы не конфликтовать по VKApiClient).
- Каналы = broadcast-сообщества (как в #DIALOGS-TAB). Счётчики: непрочитанное канала НЕ входит в общий счётчик диалогов (VK web: бейдж мессенджера считает только ЛС/беседы).

**Спек:**
1. Верифицировать приёмный контур: типы 61/62 парсятся корректно? Каким образом UI чистит стейт (таймаут 5с)? Показывается ли «X печатает…» в шапке/над полем ввода чата? Починить/доделать честно, с логами `#TYPING-FIX`.
2. `MessagesScreen`: строка диалога при живом Typing-событии (для этого пира) показывает «печатает…» (в чатах — имя пользователя) вместо сниппета; таймаут-гашение; не ломать подстановку превью.
3. Каналы-счётчики: исключить unread каналов из сводного счётчика (бейдж дока) и из таба «Непрочитанные»/«Все» агрегатов; собственный бейдж канала в списке НЕ трогать. Трассировать агрегацию по коду (не по догадке).
4. Сеть каналов: диагностировать жалобы «сеть проблемы при просмотре раздела каналов и содержимого отдельных каналов» — какие запросы (getConversations/getHistory/wall?), ошибки (таймаут/пусто/пагинация), по AppLog-меткам и коду; исправить причины (напр. повторные запросы из-за сброса курсора, отсутствие ретрая, гонки обновления списка). Без переписывания архитектуры.

**Зона:** LongPollClient.kt, ChannelWebSocketClient.kt, ChatDetailScreen.kt, MessagesScreen.kt, SovaApp.kt (только counter/typing-части). **Запрещено:** VKApiClient.kt (setActivity — шаг 18-θ), ShareSheet/ShareToChatSheet, FeedScreen, CommunityScreen, SettingsScreen, SovaPrefs.

**Приёмка:** typing в списке диалогов и в чате реально отображается и гаснет; бейдж дока не включает каналы; канал непрочитан → бейдж не растёт; сеть каналов — без повторных ошибочных запросов (лог-метки).

## 18-β. Шеринг: полный паттерн SharePanel VK web

**Текущее состояние (факты):**
- `components/ShareSheet.kt`: «На своей стене» = `wall.repost` (214), `repostToGroup` (183) = `wall.post owner_id=-gid, attachments=wall{owner}_{id}` (VKApiClient:5879), «Избранное» = self-chat, pinned (#FAVE-SELF-CHAT, 386-392).
- `components/ShareToChatSheet.kt` — отправка в ЛС/чаты.
- VKApiClient: `messagesSend(peerId, message, attachment)` (5286), `wallPost` (5708), `wallRepost(object_, message)` (5763), `repostToGroup` (5879), `wallPostWithAttachments` (6341). `bookmarksAdd`/`faveAdd*` — НЕ найдены.

**VK web паттерн SharePanel (явно, vk.com SharePanel):**
- «На своей стене»: для поста — `wall.repost` `object=wall{owner}_{id}` + message; для вложения (фото/видео/док/аудио) — `wall.post` `owner_id=свой` `attachments=photo{owner}_{id}|video…|doc…` (wall.repost тоже принимает `object=` только wall/клонированные объекты — для сырых вложений wall.post). Проверить текущую передачу message/comment в оба метода.
- «В сообщении»: `messages.send` `peer_id` + `attachment=wall{owner}_{id}` для поста; для файлов — прямой attachment-строкой (`photo…`, `doc…`, `audio…`), для внешних файлов — upload-контур уже есть (docs.getWallUploadServer и т.п.) — переиспользовать, не изобретать.
- «Подписчикам сообщества» (если админ/редактор/модератор и can_post): `wall.post` `owner_id=-gid` `attachments=wall{owner}_{id}` + message. Право определять по данным groups (is_admin/can_post из уже загруженного GroupInfo — CommunityScreen; в универсальном шите — groups.getById fields=can_post,is_admin при открытии группы-цели).
- «Избранное»: у VK web — закладки (`bookmarks.add` type=post/item; старое имя fave.addPost), у VK-приложений — self-chat «Избранное» (messages.send себе). Реализовать ОБА честно: «В закладки» = bookmarks.add (если бэкенд метода не поддерживает — показывать реальную ошибку API, без маскировки), «Избранное» (self-chat) — починить существующий путь: корректный свой peer_id (users.get / текущий userId из SovaApp), attachment поста/файла, подтверждение.
- Файлы: шеринг из поста с doc/audio/photo должен строить валидные attachment-строки (общий хелпер buildVkAttachment уже есть после #ATTACH-UNIFY — переиспользовать).

**Спек:** единый ShareSheet с разделами VK web: стена / сообщества (где могу постить) / чаты (ShareToChatSheet) / закладки / избранное / копировать ссылку. Каждый пункт — реальный API-вызов + реальный результат (тост/ошибка). Трассировать все точки входа (FeedScreen, PostDetailScreen, CommunityScreen, UserProfileScreen, ClipInteractionsSheet, ShareToChatSheet) и привести к одному паттерну. `repostToGroup`: проверить наличие message-параметра в args и прав.

**Зона:** ShareSheet.kt, ShareToChatSheet.kt, VKApiClient.kt (только share-методы: wallRepost/wallPost/repostToGroup/bookmarksAdd/new messagesSend-хелперы), PostDetailScreen.kt (точки вызова), CommunityScreen.kt (точка вызова). FeedScreen/UserProfileScreen/ClipInteractionsSheet — только чтение, изменения координировать в отчёте (FeedScreen — зона 18-γ).

**Приёмка:** пост → «на стену» появляется у себя на стене; «избранное» — сообщение реально приходит в self-chat; «в закладки» — реально появляется в закладках (или честная ошибка API); шеринг в группу-где-админ — пост появляется в группе; файлы (doc/photo/audio) долетают до чата без потери.

## 18-δ. Уведомления: фильтр из «Ленты» + порядок «диалоги → новости» (волна 19, ПЕРЕСМОТРЕНО юзером)

**Уточнение пользователя (2026-09-08, второй заход):** «Раздел Уведомления пересмотри с учётом, что фильтр берётся из „Ленты“».

**Что это значит:** в VK web «Уведомления» — СЕКЦИЯ ЛЕНТЫ (vk.com/feed?section=notifications, SPA-контейнер com_web_spa_notifications — см. лента.снапшоты.парсинг.полный.md:123), её фильтры приходят из ленточного контура, а не самодельным списком. В PinoK сейчас: NotificationsScreen имеет захардкоженный список NotificationFilter (58 категорий из архива #68, строки 140-169) и клиентскую фильтрацию поверх notificationsGet (API фильтр-параметра для web-токенов не имеет — Fix #248, getRedesign без filters).

**Спека:**
1. Фильтры раздела привести к VK web-ленточному набору: категорийный список НЕ выдуманный архивный дамп, а соответствие реально показываемым фильтрам секции уведомлений ленты (сверить по снапшотам и по реальным type, которые приходит в getRedesign — честная сводка типов в KDoc); визуально — паттерн фильтра ленты (FeedScreen feedShowFilter bottom-sheet/чипы, как «Все новости/Рекомендации/…»), а не отдельный самодельный dropdown.
2. Порядок списка уведомлений: сначала класс «сообщения/диалоги» (message*/mail/group_chats), затем новостные (лайки/комменты/подписки/прочее) — стабильная сортировка внутри классов, порядок VK не трогает.
3. Системные «сплывающие» (VkNotificationsNotifier + NotificationsPoller): уведомления о диалогах — выше новостных (NotificationCompat.setCategory MESSAGE + setSortKey/dialogs-first + канал важности выше, чем у новостного канала), при пакетной постановке (поллер) — сортировать диалоги первыми; конверсии типов честно трассировать.
4. Без потери существующих функций: undo-скрытие, markAsViewed, бейдж unread, поиск — не ломать.
