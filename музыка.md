## 1. Архитектура плеера (Desktop VK Web)

Десктопный VK audio-player — обёртка над vanilla HTML5 `<audio>` **без** Web Audio API, без Howler.js, без AudioContext.

### 1.1. AudioPlayerHTML5 (модуль 722574, common.5c45ffd2.js)

Управляет **ДВУМЯ** `<audio>`-элементами:
- `_currentAudioEl` — активный трек
- `_prefetchAudioEl` — предзагрузка следующего трека на ≥80% прогресса (отключён на Safari)

Каждый элемент обёрнут в `HTMLAudioNode` (модуль 71935), который:
- навешивает DOM-слушатели: `pause/play/playing/waiting/progress/timeupdate/seeked/ended/error/canplay/durationchange`
- инстанцирует `hls.js`, если URL заканчивается на `.m3u8` или это `blob:http` (офлайн)
- `crossOrigin="anonymous"`, `preload="auto"`, дочерний `<source>`

### 1.2. AudioTaskManager (модуль 51037, b-36d0be18b54dca57.js)

Serial Promise-based очередь задач. Оборачивает: `setUrl / play / pause / seek / setVolume / updatePlaybackRate / delay`.
- Задачи выполняются по одной через флаг `taskInProgress`
- `seekImmediate()` **обходит** очередь
- `delay()` использует Web Worker для точного `setTimeout`
- `setVolume(v, fade=true, duration)` → `impl.fadeVolume()` через Web Worker тикающий 20ms (fallback `setInterval` 60ms)

### 1.3. PlaylistQueue (модуль 733615, common.5c45ffd2.js)

MobX-observable очередь:
- **Shuffle:** Fisher-Yates с закреплением текущего трека на позиции 0
- **Unshuffle:** восстановление `originalList`
- **Dedupe:** `Set` по `fullId`
- `AUDIO_QUEUE_MAX_AUDIOS_COUNT = 35` — лимит на bulk-fetch
- поддержка «empty audio»-плейсхолдеров (lazy-load плейлистов)
- Источники очереди: `VKMIX / CATALOG / MESSAGE / FEED / WALL / ALBUM / CURATOR / PLAYLIST / PODCAST`

### 1.4. AudioPlayer (класс `We`, audioplayer-lib.js)

Оркестратор. Состояние:
- `_isPlaying`, `_isPaused`, `_repeatCurrent`, `_repeatAll`
- Volume персистится в `localStorage` → `audioplayer_block_volume_<vk.id>`
- **Default volume = 0.476**
- Podcast playback rate: max 3 (не-Safari), 2 (Safari), step 0.5
- TTL кэша состояния: 2 часа (`LS_SAVED < vkNow() - 7_200_000`)
- Favicon вкладки переключается: `fav_logo / fav_play / fav_pause`

### 1.5. MediaFocus + MediaFocusChannel (модули 230414 + 204739)

Cross-feature audio focus. `MediaFocus.ensure().createChannel("audio", {pause, resume})` регистрирует аудиоплеер как focus-aware канал. Когда другой media-channel (например video) стартует — audio получает `pause()`; при остановке другого канала — может `resume()`. Построено на MobX observables.

### 1.6. MediaSession integration

`AudioMediaSession` (706278) + `updateMediaSessionMetadata` (628459) + `WebMediaSessionAdapter` (55513):
- `setActionHandler`: play, pause, seekbackward (−10s, fallback prev track на 0), seekforward (+10s, fallback next track в конце), previoustrack, nexttrack
- `MediaMetadata({title, artist, album, artwork:[{sizes:"160x160", src}]})`
- album обрезается до `30 - location.hostname.length` символов
- **НЕТ** вызова `setPositionState()`
- `clear()` проигрывает SILENCE data-URI WAV для сброса OS media session

## 2. audioUnmaskSource — критическая функция деобфускации URL

> Модуль **540477** в `b-226df83bda86a954.bc377a3ddd52ea9b.js` (также 434810 в desktop common).
> **САМАЯ критичная функция** для любого клиента, воспроизводящего VK-аудио.

### 2.1. Проблема

URL аудио, возвращаемый VK API, содержит литеральный плейсхолдер `audio_api_unavailable` + payload `?extra=<base64>#<base64>`. Прямой URL недоступен — его нужно деобфусцировать на клиенте.

### 2.2. Алгоритм (полный)

1. Сплит по `?extra=` → берём правую часть
2. Сплит по `#` → получаем **две** base64-строки: `[urlPayload, opsChain]`
3. Кастомный base64-декод с алфавитом:
   ```
   abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMN0PQRSTUVWXYZO123456789+/=
   ```
   (внимание: `O` стоит после `N`, а `0` — в середине, нестандартный порядок)
4. Первая строка → закодированный URL
5. Вторая строка → цепочка операций, разделённых `\t` (char code 9)
6. Каждая операция: `<opName>\v<arg1>\v<arg2>...` (разделитель `\v` = char code 11)
7. Операции применяются в **ОБРАТНОМ** порядке к base64-декодированному payload

### 2.3. Операции (4 шт.)

| Op | Имя | Действие |
|---|---|---|
| `v` | reverse | разворот строки |
| `r` | caesar-shift | сдвиг по удвоенному алфавиту на N позиций |
| `s` | permutation | BigInt-seeded перестановка; seed = `BigInt(vk.id) XOR BigInt(parseInt(t))` |
| `i` | alias of `s` | то же, что `s` (seed `BigInt(vk.id) XOR BigInt(parseInt(arg))`) |
| `x` | per-char XOR | `char XOR arg.charCodeAt(0)` для каждого символа |

8. Если финальный результат начинается с `"http"` — вернуть его; иначе вернуть оригинальный URL.

### 2.4. Kotlin-порт

```kotlin
// BigInt через java.math.BigInteger
// 4 transforms v/r/s/x + i (XOR с vk.id как BigInteger)
// алфавит: "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMN0PQRSTUVWXYZO123456789+/="
```

## 4. Форматы и потоковая передача

### 4.1. Два формата аудио-URL

1. **Прямой MP3 CDN** — для обычных треков
2. **HLS `.m3u8`** — для стриминга (чаще для HQ / длинных треков / подкастов)

`isHlsUrl(url)` = `audioUnmaskSource(url).includes(".m3u8")` (+ `checkIsDownloadedUrl` для PWA офлайна).

### 4.2. hls.js

Динамически загружается через `Promise.all([i.e(8870), i.e("langs/web/hls_lib")])` (desktop) или `langs/mvk/hls_lib` (mobile).

**Конфиг:**
```js
{
  debug: !!ls.get("_audio_hls_debug"),
  maxBufferHole: 3,           // сек
  nudgeOffset: 0.5,           // сек
  nudgeMaxRetry: 5,
  maxFragLookUpTolerance: 0.2 // сек
}
```

**Native HLS** (без hls.js): Safari всегда; IE Edge 12-77. Использует `<source type="application/vnd.apple.mpegurl">`.

### 4.3. Обработка ошибок HLS

- `BUFFER_STALLED_ERROR` → `stopLoad()` + `startLoad()` (restart) + stall event через `StallRater` (perf.now-based duration tracking)
- Fatal errors → `onFail({type, details, url, code})` → player `FAILED` event + `ENDED` event + auto-advance: `_playNextMarked({auto:true, reason:QueueContinuationAfterError})`

### 4.4. wrapAudioPlay

Оборачивает `audioElement.play()` Promise, глотает `NOT_SUPPORTED_ERR` и `ABORT_ERR` (остальные re-throw).

### 5.4. Restrictions & Legal

- `content_restricted` — numeric (0 = unrestricted, non-zero = restricted type code)
- `dmca_blocked` — отдельный boolean для DMCA takedowns
- `isBlocked()` = `!!dmca_blocked || content_restricted !== 0`
- `legal_notices_type` bitmask: bit 1 (val 2) = `isExplicit`, bit 2 (val 4) = `isForeignAgent` (российская метка «иностранного агента»)
- `flags_context` bitmask для kids-контента: bit 0 = isKidsSection, bit 1 = isKidsContent, bit 2 = isKidsLimited, bit 3 = isKidsEditorial
- `audio.getRestrictionPopup` (API) или `al_audio.php?act=restriction_box` (desktop) — диалог ограничения

## 6. Офлайн-кеш (OfflineAudioStorage)

> Gate: feature flag `mvk_music_pwa`. PWA-only.

### 6.1. IndexedDB схема

База: `pwa_music_storage` v1. Шесть object stores с reference counting:

| Store | keyPath | Indexes | Назначение |
|---|---|---|---|
| `tracks` | `fullId` | (none) | сохранённые аудио-blob'ы (manifest + fragments + key + covers) |
| `users` | `id` | (none) | реестр пользователей |
| `playlists` | `id` | (none) | метаданные плейлистов |
| `tracks_by_users` | `[trackId, userId]` | `track_id_index`, `user_id_index` | у какого юзера какой трек (+ timestamp) |
| `users_by_playlists` | `[playlistId, userId]` | `playlist_id_index`, `user_id_index` | у какого юзера какой плейлист |
| `tracks_by_playlists` | `[playlistId, trackId, userId]` | `user_tracks_index` (compound `[playlistId,userId]`), `track_playlists_index` (compound `[trackId,userId]`) | треки плейлиста для юзера |

### 6.2. Download flow (`toStoredAudio`)

1. `fetchService.reloadAudios(fullId)` → получить URL-tuple
2. `audioUnmaskSource(url)` → реальный CDN URL
3. `ensureHLS().loadSource(url)` → парсинг m3u8 через hls.js → `[{relUrl, levelKeyUri}]`
4. Параллельный fetch как Blob/text:
   - `coverUrl_s` → малая обложка Blob
   - `coverUrl_p` → крупная обложка Blob
   - manifest text (сам `.m3u8`) через `r(url) = fetch(url).then(r=>r.text())`
   - DRM key Blob через `l(levelKeyUri)`
   - каждый фрагмент Blob через `l(relUrl)` → `[{data, originalUrl}]`
5. Хранение: `{...audio, streamData:{streamManifest, fragments, key:{data, originalUrl}}, coverUrlP, coverUrlS}` в store `tracks`
6. Junction-записи: `tracks_by_users` (с timestamp) и `tracks_by_playlists` (если сохранение через плейлист)

### 6.3. Restore flow (`toPlayableAudio`)

1. Для каждого фрагмента: заменить `originalUrl` в manifest-тексте на `URL.createObjectURL(blob)` URL
2. Заменить key URL на свежий blob URL
3. Закодировать переписанный manifest как `Blob` с `type:"application/x-mpegURL"`
4. `URL.createObjectURL(manifestBlob)` → становится audio URL для `<audio>` / hls.js
5. Cover URLs тоже становятся blob URLs

### 6.4. Blob URL cache

Класс с `create(blob) → URL.createObjectURL(blob)` (push в `cache[]` массив) и `releaseAll()` (revoke всех). **Нет** индивидуального revoke, **нет** LRU.

### 6.5. Reference-counted deletion (`removeTrack(trackId, userId)`)

- `areNoUsersWithTrack(trackId)` — нет другого юзера с этим треком
- `areNoTracksForUser(userId)` — у юзера нет других треков
- `areNoPlaylistsForUser(userId)` — у юзера нет плейлистов
- Transaction: удалить `[trackId, userId]` из `tracks_by_users` всегда; удалить `tracks` только если нет другого юзера; удалить `users` только если у юзера не осталось треков И плейлистов

### 6.6. Quota handling

**Нет** maxSize, **нет** LRU, **нет** automatic eviction. Полагается на детекцию `QuotaExceededError`:
```js
function O(t){return "QuotaExceededError"===t.target?.error?.name}
```
Сёрфится в UI через `DOWNLOADING_TRACK_ERROR` event payload.

## 12. «Эквалайзер» — МИФ

**VK web НЕ имеет реального эквалайзера.** Компонент «equalizer» в vkcom-kit — чисто косметический (4 анимированных CSS-полоски). `_startFrequencyAnalise` в `AudioPlayerHTML5` генерирует **ФЕЙКОВЫЕ** случайные данные через `Math.random()`, интерполированные по 3-фрейм-окнам с интервалом 50ms. Нет `BiquadFilterNode` / `GainNode` / `AnalyserNode` / `createMediaElementSource`.

Также **нет** реального crossfade/gapless — есть только `_prefetchAudioEl` (второй `<audio>` предзагружается на ≥80% прогресса) и `fadeVolume` (только для fade-out неавторизованных треков). Перекрывающего воспроизведения нет.

**Нет** service worker для audio (единственная SW-регистрация — отключённый по умолчанию debug SW из b-226df). **Нет** `navigator.wakeLock`. **Нет** `navigator.locks`.

| Service worker / wake lock | `ForegroundService` + `PARTIAL_WAKE_LOCK` + `WifiLock` |
| `MediaFocusChannel.pauseByChangeChannel()` | `AUDIOFOCUS_LOSS_TRANSIENT` → `player.pause()` |
| `MediaFocusChannel.resume()` | `AUDIOFOCUS_GAIN` → `player.play()` |

## 14. Android-specific improvements (отсутствуют в web)

1. **Foreground service** (`MediaPlaybackService extends MediaSessionService`) — REQUIRED для фонового аудио на Android 8+
2. **Wake lock** (`PowerManager.WakeLock PARTIAL_WAKE_LOCK`) в `onStartCommand`, release в `onStop`
3. **Wifi lock** (`WifiManager.WifiLock WIFI_MODE_FULL_HIGH_PERF`) для стриминга
4. **Реальный эквалайзер** — `android.media.audiofx.Equalizer` (5-band) + `BassBoost` + `Virtualizer`, attach к `audioSessionId` ExoPlayer. У VK web — нет.
5. **Реальный gapless** — `ConcatenatingMediaSource` / `setMediaItems(list)` нативно, без prefetch-хака
6. **Реальная визуализация** — `android.media.audiofx.Visualizer` даёт настоящий FFT, без `Math.random()`
7. **MediaSession position state** — Android `setSessionExtras()` + auto-update позиции из Player; web не вызывает `setPositionState()`
8. **MediaButtonReceiver** — `androidx.media3.session.MediaButtonReceiver` для кнопок гарнитуры (`ACTION_MEDIA_BUTTON`)

## 15. Краткая сводка для имплементации

**Минимум для рабочего аудио-плеера:**
1. Kotlin-порт `audioUnmaskSource` (модуль 540477) — БЕЗ НЕГО никакие URL не заиграют
2. API-gateway клиент: `POST https://api.vk.com/method/audio.X`, body `v=5.205&access_token&lang=ru&...`
3. Парсинг audio-tuple (33 индекса) ИЛИ mobile snake_case-object
4. ExoPlayer + `HlsMediaSource.Factory` для `.m3u8`, default `MediaSource` для MP3
5. `MediaSession` для системных controls
6. Foreground service + wake lock + wifi lock
7. Room-кеш для офлайна (6 сущностей, reference counting)

**Желательные фичи (превосходящие web-VK):**
- Реальный 5-band Equalizer + BassBoost + Virtualizer
- Реальный FFT-визуализатор
- True gapless playback
- LRC-synced lyrics (у VK только plain text)
- `setPositionState()` в MediaSession
- MediaButton (гарнитура) support

**Критические «подводные камни»:**
- `audioUnmaskSource` требует `vk.id` для transform `i` (BigInt XOR) — без ID юзера не деобфусцируется
- HLS-фрагменты и DRM key нужно качать параллельно и хранить как blobs
- Manifest для офлайна нужно **переписывать** (заменять fragment URLs на blob URLs) перед передачей в плеер
- Reference counting при удалении: трек удаляется только если нет других юзеров; юзер удаляется только если не осталось треков И плейлистов
- `QuotaExceededError` → нужно ловить `SQLITE_FULL` / `IOException` и сёрфить в UI
- Default volume web = 0.476 (не 1.0) — стоит учесть при миграции UX
- Favicon toggling → на Android = MediaStyle notification
