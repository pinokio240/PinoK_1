## Диагнозы

### D1 (Fix #357). `isBoolean` у JsonElement
`json.get("response")` возвращает `JsonElement`; `isBoolean` есть только у `JsonPrimitive` (волна 24, messagesArchive/UnarchiveConversation). Фикс: после уже стоящей проверки `isJsonPrimitive` взять `val prim = resp.asJsonPrimitive; if (prim.isBoolean) …`.

### D2 (Fix #358). Поиск/Реакции «не работают» — корень: error-гейт съедает разделы
- Выбор «Поиск»/«Реакции» в меню → `reloadFeed()` → `fetchFeedPage` для этих разделов НАМЕРЕННО возвращает пустой NewsfeedResult (Реакции грузятся отдельным LaunchedEffect через likes.getList; Поиск ждёт запрос) → `allPosts.isEmpty()` → `errorText = "Лента пуста"` (FeedScreen 908/1036).
- Гейт `if (errorText != null && posts.isEmpty()) { ErrorView; return }` (1246) заменяет собой ВЕСЬ контент — включая поле поиска и подтабы Реакций. Раздел недостижим визуально, хотя код под ним живой.
- Вкладки Реакций сверены со снапшотом (лента.снапшоты.парсинг.полный.md §1.5): Все/Посты/Комментарии/Клипы/Видео + блок «Фотографии» внутри «Все» — НЫНЕШНИЕ LikesFilter соответствуют 1:1. ДОБАВЛЯТЬ ничего не надо — они просто были недостижимы.
- Фикс: в reloadFeed и первичном LaunchedEffect(Unit) НЕ ставить errorText из пустоты при feedFilterName ∈ {LIKES, SEARCH} (разделы сами управляют контентом; свои ошибки loader'ы уже показывают). API-ошибки обычных разделов — без изменений.

### D3 (Fix #359). Кнопка меню уезжает со скроллом
Кнопка открытия меню сейчас внутри первого item LazyColumn (уезжает). Юзер: «на верхней панели ленты». Фикс: ЗАКРЕПЛЁННАЯ панель над списком (Row 48dp, кнопка справа) — вне LazyColumn, всегда видна. Глобальный TopAppBar в SovaNavHost вне зоны FeedScreen (прецедент волны 23) — закреплённая строка в FeedScreen и есть «верхняя панель ленты».

### D4 (Fix #360). «Возможно, вы знакомы» без переключателя
Блок рисуется в ProfileScreen (вкладка «Стена», friends.getRecommendations) всегда, если VK вернул данные. Фикс: pref `profileFriendSuggestions` (default FALSE = секция скрыта, требование юзера), тумблер в SettingsScreen → Приватность, гейт загрузки+рендера в ProfileScreen.

### D5 (Fix #361). Защита/Приватность — аудит
Статически проверено ВСЁ подключено: навигация (SettingsPrivacy/Devices/VkIdAccount — SovaNavHost 1968–1990), API (settingsGeneral.get/setPrivacySettings, accountPersonal.getActivityHistoryDevices/reset(Sessions|AllSessions) — VKA 14330–14472), privacy-флаги применяются в VKApiClient (PrivacyMods/маска/скрытие last seen — 10507/10523/13544), SecurityAlertsPoller инициализирован (SovaApp 1339), logoutHash хранится с логина (ExchangeTokenStorage 474). Реальная причина «не работают вообще» у юзера — D1: сборка с волной 24 НЕ КОМПИЛИЛАСЬ, юзер сидел на старом APK. Дополнительно в Приватность добавляется тумблер из D4.

### D6 (Fix #362). Музыка: пункты меню трека
Аудит AudioMoreMenu vs MusicScreen-обработчики:
- «Редактировать трек» (isOwn) — `onEdit` НЕ передан → мёртвая кнопка.
- «Открыть альбом» — `onOpenAlbum` НЕ передан → мёртвая кнопка.
- «Удалить аудиозапись» — audioDelete работает, но список не обновляется и тоста нет → выглядит мёртвой.
- «Восстановить» — audioRestore работает, фидбека нет.
- «Не нравится» — audioAddDislike работает, фидбека нет.
- «Показать похожие» — audioGetRecommendations БЕЗ target_audio → «похожие» не по треку.
- «Воспроизвести следующей» — `onSetNext` НЕ передан; в PlayerConnection нет playNext.
Фиксы: VKA + audioEdit (audio.edit artist/title); audioGetRecommendations + targetAudio; PlayerConnection.playNext (insert в playlist + ctrl.addMediaItems после текущего); MusicScreen: диалог правки трека, удаление с обновлением списка+кэша+тостами, честные тосты на restore/dislike, проводка onOpenAlbum (параметр onOpenAlbum у экрана уже есть).
